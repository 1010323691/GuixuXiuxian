# R5 空中自动斗法：工作室统一裁决

本轮交付为可运行的独立玩法实验室，不是正式 v1.2 的战斗替换。正式版本、存档、修炼速度、资格和掉落账本保持原实现。实验代码在 `prototypes/r5-combat/`；启动及隔离边界见该目录 README。最终实测状态以 `R5_LAB_TESTING.md` 为准。

## 1. 讨论与裁决记录

五岗分别完成方案，并就 CD 定义、资源机会成本、法宝来源、Boss 评分、旧战斗兼容和画面身份混淆交叉评审。策划提出三类构筑和实际数值矩阵；架构反对复制正式伤害引擎；开发指出没有真实吸收事件就不能画盾的拦截；视觉比较三种代身并制作实际页面；QA 独立核算伤害和接口，发现节点完成状态映射问题并推动修复。不是一次性拼接五份建议。

PM实看首轮桌面/320画面后退回两项：副宝标签与身份重叠、固定器物只发射线缺少御宝感。视觉重排窄屏槽位，将重复CD交给下方技能格，并用同形器物沿真实事件路径出击/回收。进一步读审发现自然末拍立即停止会取消后续法宝击杀演出，已要求修复并由QA实际采样首/末拍位置；这些均属表现与清理缺陷，不改胜负或奖励。

| 问题 | 最终决定与理由 | 主要取舍 / 验收 |
| --- | --- | --- |
| 核心乐趣 | 战前配装与策略 → 自动观战 → 看懂胜败 → 换构筑挑战。普通攻击无需反复点击 | 自动不等于无选择；准备时可见伤害、CD、初始延迟、道具预算和机会成本 |
| 修士形象 | **稳定神识灵印代身**，固定姓名；本命与护持为两个独立器物 | 灵印只是观战抽象，不新增神识离体设定。御剑代身容易与攻击宝混淆；大型门派法相成本、遮挡高，留后续资源方向 |
| 场景 | 云海上方对峙，山峰在下层，轻微悬浮与灵气尾迹 | 不增加高度、射程、手动走位或闪避规则；不能保留地面站立人物和脚下石台冒充御空 |
| 参考语言 | 参考《了不起的修仙模拟器》的独立御宝、蓄势、飞行、回护和气迹思路，原创 SVG/CSS 实现 | 未提取或复制其素材，也不声称已查阅参考原画；以清楚的攻防因果为目标 |
| 技能与法宝 | 主技能是瞬态剑符；常驻的两件法宝按真实槽位与来源触发 | 不画免费第三件宝；归元斩、持续宝、爆发宝和护持宝均有独立识别 |
| CD | 后端以逻辑行动机会推进，准备时说明成本，画面显示“拍” | 不是现实秒表；暂停、倍速和回看不恢复 CD、不增加攻击 |
| 丹符 | 默认零使用，战前授权单 run 数量；使用占唯一主行动 | 不能无限自动喝药；授权更多不保证更优，结算显示实际消耗 |
| 世界 Boss | 十二拍输出窗口，强调个人有效伤害及参考进度，NPC 单列 | 不要求击杀巨大 HP 目标，NPC 不算个人分；实验不发正式奖励 |
| 副本图 | 三节点可回看，每节点表现真实通过、当前、锁定 | 本实验是毒→盾→汲灵的混合压力路线，不冒称正式副本配置；失败后不演后续战斗 |
| 结果权威 | 实验后端一次有界演算，前端只播放返回帧和事件 | 无正式存档与经济副作用，不能用实验通过代替未来正式迁移验收 |

## 2. 空中斗法的动作语言

修士灵印保持稳定身份；本命、护持器物具有不同的固定待机位置、轮廓与标签，姓名、气血和 CD 不随轨道转动。敌方用毒纹、炉印、星盘等悬空轮廓区分机制，不要求复杂人物模型。

| 真实动作 | 表现 | 玩家应能读出的信息 |
| --- | --- | --- |
| 持续宝 | 细梭沿短弧离轨、命中、归位，触发频繁但每次较轻 | 稳定压制，不是每帧都在制造伤害 |
| 爆发宝 | 依据真实剩余 CD 分段聚光，释放时集中冲击，再收束等待 | 预热、爆发窗口与长真空期；两个槽位错峰，不假齐射 |
| 护持宝 | 器物回护灵印，展开灵罩；仅 `shield_absorb` 实值事件触发拦截反馈 | 展盾不等于已吸收；毒不因罩的存在被假阻挡 |
| 主技能 | 临时剑符与较强剑气，本方主行动标签 | 不与永久法宝混淆，18 灵力、CD3 的代价可查 |
| 敌方 / 状态 | 敌→我方向的轨迹，蓄重击预兆、毒纹、破盾、汲灵分别反馈 | 不只靠换颜色；数值与文本始终保留 |

参考不是叠满粒子：同一时刻突出一条主要攻击路径和一处状态反馈，保留空域留白。不使用遮屏白闪或强制镜头晃动。减少动态模式保留器物轮廓、槽位、CD、状态与实录；暂停、跳帧、换节点、新演算须清理旧动效。

`frame.decision_reason` 来自真实选技分支；`shield_absorb` 仅在实际吸收大于零时记录，来源 secondary、目标 player，位于敌方气血伤害之前。视觉不依据猜测制造格挡、额外伤害或法宝碰撞抵消。

## 3. 实际数值评审与保留的取舍

策划运行 60 格矩阵，原始输出见 `artifacts/r5-design/matrix-initial.json`。它验证候选而非正式成长平衡：玩家攻击100、HP600、MP60，主技200伤/18MP/CD3；持续双宝40伤/CD2、初始错峰0/1；爆发双宝120伤/CD6、初始2/4；护持为一持续攻击宝及90盾/CD4。

- 同样十二拍内，双持续与双爆发理论均贡献480伤，实际击杀时点、承伤和跨节点相位不同。
- 零补给强攻毒巢：持续第7拍胜，爆发第7拍败且敌剩20血，说明早期稳定输出有价值。
- 零补给均衡熔炉：持续与爆发败，护持第13拍胜、剩130血，防护并非无用的低 DPS 选择。
- 零补给均衡混合连战：持续败，爆发第18拍胜剩32血，护持第22拍胜剩155血，存在速度与容错取舍。
- 更多补给未必更优：占行动会挤掉输出并改变相位。比如均衡爆发连战预算增加后可从18拍/32血变22拍/3血。策略当前并非全局最优，复盘应明确实际原因，不能承诺“自动一定最聪明”。

新增元数据和空战因果日志前后，开发逐场对比60组 HP/MP/CD/结果/指标/节点不变；仅允许新增吸收日志和实际决策原因。QA仍须独立复验，不把开发的等值检查当独立验收。

## 4. 正式接入路线与门槛（本节为接入前的规划；已按较轻方案实装，实际范围、取舍与未做项见 [R5_INTEGRATION.md](R5_INTEGRATION.md)）

1. 从现有正式规则抽单机会 resolver，不复制第二套经济/掉落引擎；覆盖序章和九类世界战斗。旧进行中战斗保留原 HP/MP/毒/盾/回合/预约，可委托旧规则，下一场再进入新规则。
2. 正式自动推进使用有界小块请求、battle_id/cursor/request_id/revision 与持久化战报；每次事务包含世界时钟、预算、胜负与奖励，重试只消费和派奖一次。GET、动画及后台标签不结算。
3. 战前可一次授权推进**当前 run**。无实质选择的战间不强制重复点继续；遇真实分支、失败或方案变更暂停，不得自动开启下一 run 或消耗另一份入场资格。可选逐战停留。
4. 正式沿用既有免费战间整备等值效果须另行冻结字段；建议保留既有 HP/MP 补救、run 内 CD 连续，整备/播放不免费加速 CD、不补回已耗丹符。实验无营地，不能把实验连战平衡直接套入正式有整备路线。
5. 保持月余修炼、540×境界系数/日、总加成15%上限、资格8h恢复/容量3及装备奖励账本。修炼宝不能免费兼得战斗宝完整收益；旧法宝实例的映射和伤害预算必须重新评审。

正式验收必须覆盖：同初态分块1/N一致、倍率/跳过一致、旧档/断线恢复、重复请求、预算/预约/奖励守恒、普通根骨补救、三机制/精英/Boss分档、所有战斗入口图形可达。实验的14项独立测试和真实浏览器不能替代这份集成清单。当前没有把这些未来能力标为完成。

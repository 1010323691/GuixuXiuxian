## 2. 世界Boss必须先解决的评分语义

**当前单人“把固定HP打到0”模式，所有成功玩家造成的有效总伤害基本等于Boss HP，因此不能直接拿总伤害做高低奖励。** 原始攻击数字相加又会鼓励过量伤害、反复回血刷分，无法反映真实输出。

推荐设计为明确标注的本地世界Boss限回合挑战：固定Boss/难度与若干玩家回合窗口，成绩取本次窗口内实际削减气血的伤害，按透明阈值决定材料/法宝碎片/装备档位；提前击杀按最高档处理。Boss属性在创建挑战时冻结，不跟随本次玩家战力自动等比例升高，否则升级收益被抵消。可以有NPC参战叙事，但NPC伤害必须真实单独记录，不算玩家成绩。

需要策划冻结：回合窗口、失败/撤退是否有参与奖、伤害分档、挑战/掉落频率、是否允许无限练习、宠物/同行等伤害归属、过量伤害和敌人回血如何计分。建议记录 `min(本次伤害,命中前敌方HP)`，奖励评分上限明确，不因刷治疗或重复日志增加。难度和境界档位不同的成绩不混排行。

只针对未来新长线profile统一成长账户；旧自由行动profile和序章应保留已交付语义，不能静默拉长老角色成长。必须审计执行、目录、预览、日志、测试五层，不能只改按钮或突破门槛。

| 入口 | 当前实际直接XP | 新长线建议处理 |
| --- | --- | --- |
| world_cultivate | 12+4×阶段+木根/聚灵阵/称号，每次可重复 | 改为持续修炼解释/可选额外活动，不再无限按点击加XP；相应加成统一变成获批基础速率加成 |
| guard首胜/重复 | 首20+6s，重复8+2s | 主奖改掉落；若保留当日成长辅助，走唯一类别资格，不能与副本160重复算同一次完成 |

| 碑文奇遇 | 配置reward.xp=20/8 | 配置型通用奖励同样须被成长账户拦截，不能漏过内部gain路径 |

| 未来丹药、法宝、里程碑和奖励箱 | 当前多数没有此XP效果 | 禁止新增“通用奖励字典xp”旁路；修为道具若存在，也必须定义稳定资格和总账归属 |

旧月度表包含每日常规360×阶段系数和基础540。如果把活动直接XP全部删除，原35–40日结论立即失效；不能还引用旧模拟。用户说“主奖掉落”不自动等于“禁止任何辅助成长奖励”。PM需冻结：保留有限辅助成长，还是由基础+修炼型法宝重新承担月余目标，然后由QA重算。法宝新增速率也不能不入预算就叠在原15%之上。

所有速率变化（换法宝、强化、突破、根骨/阵法切换）先结清旧速率区间再换新速率。GET只预览；POST同一事务同步成长、处理换装/掉落/消耗和请求记录；离线不推进NPC、拍卖、战斗或自动副本。

## 4. 装备数据兼容与迁移建议

当前模型是 `inventory[item_id]=数量`、`gear[item_id]=强化等级`、`equipment[槽]=item_id`，**同类多份共享强化等级，不是装备实例**。现有字段只允许已知目录ID，严格校验和所有三槽投影都要配套升级。

推荐新长线掉落使用独立实例：`uid,template_id,tier,quality,enhance,effects,source_receipt`，装备槽引用uid；修炼/战力法宝另有明确槽位和互斥/兼得规则。材料、药品、碎片仍用可堆叠数量。战力派生函数和成长速率函数分别消费法宝效果，不把临时加成永久写进基础属性。

兼容注意：
- 旧item ID、强化等级、已装备状态、备用数量和任务交付语义都要保留；不能把所有旧器归零、删除备用或让交一件任务删掉整类强化。
- 不可将上限999999的旧数量逐份展开成999999条实例。保留可拆分的旧模板堆叠/兼容记录，装备或分解时按需实例化，或采用经过验证的等价批记录；迁移不能凭空增减资产。
- 旧同类共享强化是实际语义，迁移需明确每份是否保留原级别；不要默认只有当前穿戴一件获保留。该规则会影响旧档财富，须由PM明确并测试。
- 增加schema/content版本，显式备份，current与slot一起迁移；保留profile/revision/请求历史。旧进行中战斗以冻结旧算法完成或用明确转换协议处理，不套新掉落表重算旧胜利。
- 仓满掉落走有uid/来源的待领容器，不用普通gain截断；领取、分解、强化、装备、寄售/绑定限制与重复交付都要原子校验。预览不能直接引用后端私有对象而让客户端提交stats。

## 5. 世界Boss与掉落防重复结算

现有request_id+revision只防同请求重发/旧页写入，守关首胜键只是stage，副本首通键只是dungeon:difficulty；这些都不是新世界Boss唯一参与/结算身份。

建议服务端分配 `profile_id + encounter_id + attempt_id`，冻结Boss配置版本、难度、开始时装备/速率/战斗属性，以及该场可获得的奖励资格。结束时在同一事务内：锁定终态 → 验证伤害汇总 → 决定档位和完整掉落清单 → 写唯一settlement receipt → 扣可用次数/资格 → 发放或登记待领 → 写请求记录。唯一约束使用稳定玩法身份，不用客户端ID、可回档tick或仅日字符串代替。

如采用随机掉落，种子/抽取位置或最终掉落清单必须在事务中持久化；失败回滚与重试不能重新抽奖。也可先采用透明的确定性分档掉落与碎片保底，降低首轮实现风险，但这必须是冻结策划规则。

新长线官方load已批准保留slot外成长/活动资格。若新装备掉落资格也放slot外，**仅保留“已领”标记但回退背包会吞装备**；必须同时保留不可回退的掉落/拥有权账本，并以保存时已见receipt合并后获装备，或把该奖励完整回溯。不能一半回退、一半不回退。推荐与架构统一“资格+奖励权益+当前持有/消耗”的归属，明确分解、出售、强化和转化后的load规则，防原物与转化产物同时复活。

旧自由行动模式仍可完整回溯本地世界，不把其正常load称作弊；新模式说明真实保留边界。整库备份/本地改档不在可信服务边界内，不宣传绝对防作弊或真实共享世界Boss。

# R4 首周推进与熟练减负：界面方案

状态：资格、扫荡与七段/精英投影已冻结，static首轮接入中；尚未完成真实浏览器验收。不修改规则、玩家存档或已交付v1.1归档。已读AGENTS、岗位规范、FIRST_WEEK_AUDIT、FIRST_WEEK_DESIGN_AUDIT及FIRST_WEEK_QA_AUDIT；不以旧测试通过证明新节奏成立。

## 1. 目标与当前缺口
本轮应让玩家看懂“现在能拿什么、过多久恢复、下一段内容是什么、熟练关如何省操作”。沿用11页、深墨青手札、真实目标链和持续潜修，不增加独立签到壳或空菜单。

现有界面仍有共享UTC日3次文案，不能表达同日8小时恢复；副本页面只有手动三战，缺少已经战胜关卡的快捷结算区分；现有总览目标能定位动作，却没有七段首周任务及精英/装备追求的持续状态。需要真实新投影与规则，不能只改按钮名称。

PM已初裁：基础540×境界系数/日及加法15%上限不变；curve_v2目标为无加成且及时手动突破的12小时结丹、第2日元婴、第5日化神、45基础日封界，不是人人固定时刻保证解锁。资格入世初始3、每8小时恢复1、容量3，进行中run预约占容量，满额不囤隐形恢复时间。已同章同难真实手战成功的副本可快捷结算，世界Boss不可扫荡；奖励与原资格/保底/权益共用。

## 2. 界面落点与主路径
- 总览：保留最多3条真实缺口目标，增加紧凑的资格余额/恢复提示与当前首周段落。优先“可领取→可推进→下个真实条件”，不是每天出现更多无关actions。
- 潜修摘要：继续显示小数修为、当前速率、当前阶段成本/ETA、小境界和非XP缺口；曲线完全来自后端，旧档/新曲线标签可辨，不在前端硬编码12小时或旧1620成本。
- 秘境副本：同一副本/章节/难度工作台并排区分“手动挑战/首次通关”和“熟练快捷结算”。先看条件、收益与成本，再执行；不把扫荡做成自动离线代打。
- 闻道：七段任务的完整来路、双目标状态与奖励。默认突出当前可做段、下一段条件；已完成未领奖不折叠消失，旧段可回看。总览可直接定位对应真实任务动作。
- 精英/装备：精英挑战放现有探索工作台，人物比较仍用实例UID与后端前后数值。奖励回执能说明来自哪段任务/哪名精英，链接至比较或材料用途。

主路径：读取恢复后的余额→选择当前可推进段/副本→首次手战或对熟练关快捷结算→实际掉落及来源→比较/强化/配装→下一难度或精英→新地域和段落。基础持续增长，无资格时可做练习/材料/社会/任务；不把“本次无新装备”误写为“任何奖励均为0”。

## 3. 必需投影（与架构/开发冻结前为建议）
所有可执行入口继续使用pages标准actions/fields/confirm，前端不造奖励请求、消耗公式或资格判断。以下可采用等价字段名；须有稳定机器ID，不解析中文title决定逻辑。

| 能力 | 所需权威信息 |
| --- | --- |
| 恢复资格 | mode/version、available、reserved、capacity、server_now、next_at(满额时null)、interval_seconds、恢复/满额/回拨状态及可读说明 |
| 新成长 | profile/curve_version与标签、当前required、stage/next/milestone、准确条件、available/rate锚点及ETA依据；旧档折算结果若适用须明确 |
| 七段任务 | stable id/order/title/description、解锁条件与状态、当前/目标进度、奖励清单、已领/待领/未完成、关联真实page/action/params；有时间条件时服务端unlock_at或可读说明 |
| 精英 | stable id/name/身份说明、解锁与战斗准备、机制/反制、首通/重复奖励及状态、装备目标/来源、真实挑战action |
| 快捷结算 | 同章同难手战证明/熟练状态、enabled/reason、信用/补给成本、实际奖励预览/确定保底/容量待领规则、真实action及必要confirm |
| 回执 | 稳定run/receipt身份、manual或sweep来源、章节难度、资格实际消耗、物品与材料、保底变化、入包/待领状态 |

推荐资格位于`view.world.loot.credits`或等价只读对象；七段与精英可以复用带稳定id的sections和标准actions，不强制增加复杂组件协议。活动/任务若置于普通长列表，需稳定id或kind供前端置顶，不以文字匹配猜测。

## 4. 资格余额、恢复与时间表现
默认显示“可用X / 容量3”，有预约时另示“进行中已预约Y”。冻结契约中available已经扣除预约，available+reserved不超过capacity；同时说明可用与预约占用，不能让用户看到3可用却被提示只剩2可用。界面不同时展示两套来源不同的资格数。

有恢复计划显示下一次恢复的客户端本地时刻及剩余时间；满额显示“已满额，使用后继续恢复；基础修为仍增长”，不倒数不存在的下一份、不承诺超过容量的隐藏存量。UTC日项目/世界Boss仍单列UTC周期，不能把滚动资格称为每日凌晨重置。

倒计时仅展示，按server_now锚点与单调经过时长计算。到0后显示“等待服务端确认恢复”，触发/等待只读GET再展示新余额；绝不客户端+1、不发送领取恢复资格动作。回拨时停止虚假倒数并解释服务端时间校准。周期GET沿R3同revision文本patch，不替换表单或当前焦点；跨revision提示同步。

run中显示“本次已预约资格，续战不再重复占用”；失败/撤离时是否释放或保留预约由后端状态说明。满包仍保留完整待领权益，不能将背包满误写为资格已恢复或奖励丢失。官方load/重启不刷新恢复水位、预约或保底。

## 5. 七段首周任务与三个精英
七段采用短章列表，状态为未解锁/可接/进行/可领/已领（以冻结API为准）。每段明确：为何现在开放、两个真实目标分别完成多少、可得物品用途、与下段关系。日序是引导，不自行等价为现实日签到；若实际根据境界/行为解锁，就写条件，不显示伪“明日必开”。

优先主面板显示当前段与下一段；可领取段在列表/总览有显著状态，七段无失效，可持续补做，不能擅自吞权益。点击目标只导航并定位真实动作，不自动接取、战斗或领奖。新增任务奖励不直接发XP、不暗加15%乘区。

精英明确其独立名称与“首周精英”身份，不与阶段劫影、三战副本末Boss、12回合世界Boss评分混淆。挑战前给机制/反制、风险、装备准备与首通/重复奖励；战斗仍有置顶指令与状态，实际掉落提供来源。若精英奖励指向装备追求，必须能比较并实际装备，不能只在叙事里说“得到神兵”。

## 6. 手动首通与快捷结算
同一所选副本/章/难度显示两个清楚入口：
1. **手动挑战**：用于首通、新难度、尝试构筑和机制；标明本次正式掉落或练习状态。
2. **快捷结算**：仅在服务端证明同章同难已真实手动胜利后开放；展示对应证明与尚缺条件。不得沿用旧审计的“必须3胜+故意受毒反制”候选，最终门槛以PM冻结API为准。

快捷结算预览必须明确同一资格消耗、丹药/补给成本、与手战相同的确定性奖励/保底、实例容量/待领；普通单次结算可按后端confirm轻量确认，不每次多弹无用窗口。不能用普通“领奖”文案掩盖资格和补给消费。

不可用时保留入口与完整原因，例如未手战通关、未解锁章节/前难度、资格未恢复、补给不足、进行中活动冲突；提供真实手战/补给入口，不能仅灰色。失败/条件变化不消耗、未知结果锁住写入并同request_id重试，实际奖励和消耗以后端提交结果为准。

扫荡不代打世界Boss，不凭空推进个人伤害或初次机制成就；是否计入日周目标、熟练次数及世界行动由规则明确并投影，UI不借“相同奖励”自行推断这些行为事实。首通奖励、常规掉落和恢复资格分开展示，不能多领首通或用新请求重置保底。

## 7. 风险与讨论记录
- 已向架构提出预约语义风险：可用余额、预约占用、总容量和下一恢复必须同一权威口径；满额不积隐藏时间，倒数归零不自动生成前端余额。
- 已向策划提示七段不能成为签到壳、三精英不能与旧Boss混名、扫荡门槛不强迫故意挨毒；已向开发请求稳定section/action标识与奖励预览，冻结前不修改static。
- 新曲线迁移需要可读版本/折算说明；UI只显示权威目标，不能以新曲线12h口号说明旧角色所有进度。
- 熟练证明必须匹配同章同难；选择预览与实际点击不得跨章节混淆。会保留选择并定位真实action，避免预览难二却触发默认难一。
- 背包、资格、保底与回执必须一致。界面成功提示发生在事务确认后，重复响应不再次播放发奖或虚加余额。

## 8. 移动端与验收计划
320px用两行资格摘要（可用/预约、下一恢复/满额），不放超宽时间轴。七段默认当前和下一段，其余可展开；精英/难度/装备目标纵向展示，品质同时有文字，禁用原因可读。保持>=44px触达、键盘焦点/标签、确认可取消；恢复校正和领奖反馈不夺走正在填写的焦点。

后续真实浏览器至少验证：初始3；耗尽后8/16h真实恢复；容量满额/不囤时间；run预约/失败续战；0时刻等待权威校正；同章同难手战→快捷解锁→实际等价掉落/保底；未首通/补给不足/无资格不消耗；七段真实目标与精英掉落→装备比较；同ID重试/多页冲突/load/重启；桌面1440×900与320×900只读校正不丢草稿/焦点。

低负担验收记录相同收益流程的实际点击/战斗数与浏览器操作用时，不用API执行秒数等同真人会话。资格恢复模拟、首周七日路线与月余数学也不能冒充七个真人自然日观察。当前只有方案，无R4功能通过声明。

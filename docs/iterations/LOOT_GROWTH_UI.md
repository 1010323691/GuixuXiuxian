# 掉落驱动成长：界面与交互独立评审

状态：仅文档评审，不修改 static、规则、存档或服务。已按PM转达的R3最终方向收束，取代R2活动直接修为提议；策划精确表尚在修订。涉及新装备、法宝、世界Boss、离线增长的内容均未实装，本文不将候选数值或界面等同已完成。

## 1. 评审结论与现有入口
推荐以“选目标掉落→准备构筑→挑战合适难度→看到具体奖励→比较并装备/养成→战力或修炼速率变化→挑战下一档”作为实际主路径。副本与活动主奖为装备、法宝、材料、道具，不直接发修为；活动通过掉落和养成间接提高持续修炼效率或战力。

沿用现有11页工作台，避免另加一排空菜单：
- 人物页：当前装备槽、法宝与成长方向、背包筛选、装备比较及效果前后对照。
- 秘境副本页：难度选择、掉落预览、首次/重复奖励、当前挑战；世界Boss作为清楚的子区域，不能混称现有阶段劫影。
- 四艺/洞府页：材料用途、装备强化、法宝养成与修炼来源，目标物品能定位到实际可用动作。
- 闻道/总览：今日推荐内容、已完成与剩余掉落机会、修为增长摘要、近期奖励来历。
- NPC坊市：掉落物可交易/绑定/可制作的实际规则及价格；不能把掉落全部自动换成钱。

现有通用 sections/rows/actions 能展示概述、门槛和按钮，但缺少结构化装备比较、奖励追溯、实时增长锚点和个人Boss伤害档。单纯新增几十条 action 会重现长列表，不能视为完整新体验。现有“默认8项+搜索”继续保留，但当前挑战、待领取奖励和可直接提升构筑的关键操作不应藏在第九项之后。

## 2. 装备与法宝：看懂提升后再行动

### 装备比较
从副本回执或背包选物→显示物品身份/品质/部位/等级/强化/来源→与当前同槽装备并排比较→查看后端计算的属性和战力变化→装备→顶部构筑摘要与当前可挑战难度更新。没有旧装备时明确“当前为空槽”，不把空槽显示为损坏数据。

比较至少包括：当前物品/候选物品、基础攻击/生命/防御或实际生效属性、总战力前→后及差值、装备条件、绑定/替换去向、是否占用唯一槽。战力不是保证胜利，不能用“高于推荐值必胜”替代实际战斗预告。双向增减同时展示，降低某项时保留负号与文字，不只给绿色总提升。

同名物品若有不同品质、词条、强化或耐久，必须有稳定实例ID；若R3仍为模板级确定装备，则按模板+等级区分，不假造随机词条。前端不从名称猜品质，不自行加权计算战力。普通可逆换装不反复确认；拆解、吞噬、不可返还强化或覆盖唯一法宝时展示明确对象、消耗与损失，再按后端confirm执行。

### 两类法宝
法宝清楚标“潜修向：提高持续基础修炼效率”或“斗法向：提高战力/战斗能力”。列表筛选按方向、槽位、是否可用；不把修炼向自动判定为劣等，也不默认穿战斗装时可保留修炼装加成。

普通三装备槽保留，新增两个法宝槽“本命”“护持”，每槽可选修炼向或战力向。详情呈现当前等级、成长材料、下一阶效果、已生效槽位，以及换装后的持续修炼速率前→后、战力前→后；同槽替换的机会成本同屏可见。

修炼向法宝每件按品质提供1%–5%，两槽合计最高10%；其他来源相加最高5%，总加成最高15%。前端只展示后端分解与实际生效值，不另开乘区、不把已卸下法宝继续算入收益。

所有改变修炼速率的装备/法宝操作，先由后端结清旧速率区间再生效。确认或结果写“新速率从本次更换后生效，不追溯提高此前离线收益”，避免玩家误以为回归先换潜修装就能放大整段离线。

## 3. 持续修炼、离线增长与阶段反馈
人物摘要提供当前修为至少三位小数、当前每小时增长、基础来源分解、下一阶段成本/小境界进度。低速时不能只展示整数导致“离线没涨”的错觉，具体基础速率由R3精确表及后端投影给出。显示值从服务端 server_now、精确余额/速率锚点推算并周期校正，不把浏览器估算余额当可花金额提交。

返回游戏时用非阻断摘要说明“上次结算至本次的区间、基础增长、当前余额、按哪个境界/加成结算”；无需点击“领取离线修为”。不生成一个会过期、满仓或漏领作废的离线奖励按钮。副本和活动的掉落机会、次数及结算状态与持续修为分开表达，不显示“活动修为额度”。

增长摘要展示持续修炼与已生效加成，副本掉落回执展示装备/法宝/材料/道具，不显示直接修为奖励或日加速分账。若R3具体内容采用UTC日刷新掉落机会，按客户端时区显示并注明UTC规则；本会话东京示例为“每日09:00刷新（UTC 00:00）”，产品不对所有玩家硬编码东京，也不凭空新增日限制。

修为达到门槛后继续增长；“修为已足”与“可突破”分开，后者还要满足装备/材料/守关/剧情条件。估算只可标“仅按当前基础速率约需…，活动与加成变化未计”，不能把月余数学场景写成个人保证毕业日期。最终渡劫封界后标“潜修储备”，不显示“可飞升/仙界已开”。

新长线profile与旧自由行动profile必须有可见模式说明。新模式载入需明确修为保留及奖励权益如何处理，精确说明待架构完成资产/资格一致性方案后冻结；旧模式仍为完整世界快照。当前页脚“载入会回溯整个模拟世界”不能无条件沿用到新长线档。恢复后的未来速率从当前时刻起重开，不能倒算离线。

## 4. 副本难度、风险与奖励预览
入口先选副本再选难度，展示当前构筑、入场条件、消耗、敌方关键能力、阶段数、撤退/失败损失、奖励规则。难度建议至少具备可理解的递进关系；具体档数、命名、系数与掉落由策划定，不由UI新增。

每难度区分保证奖励、可能掉落、首通追加、重复可得、剩余机会/资格。高难实际提高的装备/法宝品质、数量或材料档次要逐条对照，不只写“奖励更好”。若确定性轮替或保底，则展示准确轮替/保底进度；若引入随机概率，则显示服务端概率，不以金色边框暗示必出。不可获得物品不得混进本次奖励预览。

准备面板提供“查看当前装备→比较候选→补材料/强化→返回所选难度”的路径，保留选择而不重新开一次副本。条件满足但风险高可以提醒，不把推荐战力当隐藏硬门槛；真门槛由后端enabled/reason表达。

战斗持续采用已有置顶意图、8条指令和全局返回战场入口。通关后具体回执展示实际掉落及数量、是否首通、难度/副本来源、已入背包或待领取状态。只有确实需要手动结算的奖励才放“领取”；自动入包显示“已入背包”，不能再制造第二次领按钮。

## 5. 世界Boss：伤害决定回报，进度透明
世界Boss专属区域注明“本地NPC模拟”，说明本轮ID/状态、Boss气血与机制、固定回合挑战规则、玩家个人单次最高有效伤害、NPC模拟贡献/榜单口径、挑战成本/次数与结算时机。个人伤害奖励与排名奖励分别标注，不能把NPC排名误作个人伤害档；不暗示有真人争抢。

主状态行必须同时给出：
- 本次挑战有效伤害、本轮个人单次最高有效伤害及固定回合口径，不把多次挑战伤害相加。
- 当前达到的奖励档及该档装备/法宝/材料/道具清单。
- 下一档阈值，以及服务端给出的“还差X有效伤害”；最高档显示“已达最高档”。
- 本轮可领取状态：尚未达标、累计中/待结算、可领取、领取处理中、结果待确认、已领取。

“有效伤害”用实际结算值，每次固定回合挑战结束后与本轮个人最佳比较，不跨次相加；过量伤害、护盾、退出和败退的细则由R3精确表及后端投影提供。UI不从客户端攻击动画、敌人HP差或名义伤害累加。挑战前可以显示已有档位和下一档差额，但不能保证“再打一刀必升档”，除非服务端预览精确说明。

领取成功后显示本轮ID、伤害档、此前已领、本次补发差额与保存状态；同ID重试只提示“已处理，已同步奖励”，不重复飞入物品、不再追加一份奖励日志。没有新差额时，换新请求ID也只能显示已领或明确拒绝；后续单次最高有效伤害提升且产生新差额时才显示可领取补差。提交后丢响应保留pending原信封并锁住重复领取，刷新后重试同ID。进入下一轮时清楚区分旧轮已领取与新轮未达标，不能把旧伤害误画为本轮进度。

已定采用固定回合个人单次最优成绩与已领奖差额结算；界面明确“当前可补领差额”，不再采用一次最终档领取提议。档位、回合数、差额计算与具体奖励等待策划精确表，不由UI推导。

## 6. 奖励可追溯与跨系统引导
近期回执不能仅是一句“获得若干奖励”。最少显示来源副本/活动/Boss轮次、难度/伤害档、完成或结算标识、实际物品ID/名称/数量/品质、是否入包及一次性状态；已穿戴物品还可在详情看到最初来源。回执可跳人物比较、四艺材料用途或再次挑战，但导航本身不领奖。

背包容量/钱包上限导致无法全部入账时，投影“待领取/暂存”及缺少容量，不能显示已入包后实际丢弃。消耗型法宝成长材料若不足，给出已开放可获取副本/活动定位，不能只有去一个尚不存在菜单的按钮。已有材料和重复掉落有实际用途或明确可出售/拆解规则，不默默自动折价。

PM已转达冻结：普通三装备槽+本命/护持两法宝槽，每槽可选修炼/战力；修炼法宝两件最高10%+其他5%=总15%；活动不发直接修为；Boss固定回合单次最优成绩+已领奖差额。剩余待落实为副本难度奖励精确表、Boss回合/档位/差额表，以及新长线load后物品与领奖资格的一致性方案。

回档权益为已转架构、尚待落实验收的风险：若装备资产随slot回退、Boss物品领奖资格却放slot外不回退，玩家读档可能永久丢失已得装备；反之若资格回退但资产不回退可能重复领。需以架构最终资产/资格一致性方案验证，不能在UI统一写“奖励已领”掩盖不一致。旧R2外置道行/日加速账本不自动决定R3装备掉落语义，不假定问题已解决。

## 8. 窄屏、可访问性与完整状态
320px装备比较改为纵向“当前→候选→变化”三段，保留同一属性顺序、单位和负号，不使用必须横拖的大表。品质用文字，方向用标签，增减同时给符号和描述；不只靠红绿/发光区分。Boss伤害档用简洁进度与当前/下一档数值，不把所有档做横向超宽阶梯。

当前战斗和待领奖回执始终可达；新物品比较可收起但不要打断每个普通掉落。离线回归摘要非阻断、可回看，不制造反复弹窗。所有比较、难度、确认和领奖支持键盘，焦点回到触发入口，失败后保留选定副本/难度/装备和填写内容。

加载/空背包/无同槽物品/未达条件/进行中/结果未知/服务拒绝/容量不足/已领取分别显示，不用一个“暂无数据”掩盖所有状态。时间异常显示实际校准说明，不让浏览器假增长持续数小时后突然扣回；客户端估算始终有服务端校正边界。

## 9. 完成标准与验证边界
后续不能仅用新菜单验收。至少实际跑通：
1. 低难获装备→比较→装备后战力变化→更高难可行且奖励提升→刷新/重启保持。
2. 潜修法宝装备→旧段已结清、新速率生效→模拟离线→回来显示正确区间/余额；切回战力法宝不追溯改过去收益。
3. 不同单次有效伤害得到对应Boss档位，多次低伤不能累加替代高伤；下一档差值准确。已领低档后提升成绩只补应得差额，未提升无差额；同ID重试/新ID重复/丢响应/多页不重发同一权益。
4. 副本/活动只有已定义的装备法宝材料道具奖励，不绕路直接发修为；首通/重复、容量不足、旧slot与当前资格一致性均有证据。
5. 真实浏览器覆盖人物/副本/世界Boss/掉落回执、三类字段、键盘及320px。注入时钟的离线测试不宣称真人玩满月余；R3数值模拟通过不等于应用已实现。

本轮仅独立界面评审，未创建按钮、未运行新系统测试、未修改static。待R3与数据/交互协议冻结后再实施。

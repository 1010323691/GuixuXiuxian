# 独立测试与交付验证

## 执行方式
在仓库根目录运行：

```sh
python -m unittest discover -s tests -v
python -m tests.browser_smoke
```

第一项仅依赖 Python 标准库。第二项需要 Python Playwright 及系统 Chromium，当前环境路径为 `/usr/bin/chromium`；脚本明确指定该路径，不依赖 Playwright 下载浏览器。游戏本身不依赖上述浏览器测试包。测试失败保留原始退出码，不以输出文件存在代替通过。

每个 HTTP 测试和浏览器脚本均创建自己的临时数据目录、回环随机端口及 Python 子进程，结束后关闭进程并清理测试数据，不读取或改写玩家默认 `data/`。坏档与写失败注入仅作用于临时数据库。若需排查，可复现相应单项 `python -m unittest tests.test_game.GameHTTPTests.test_database_lock_rollback -v`。

## 已验证范围
- 从新角色开始，经真实 HTTP 与真实页面分别执行 GDD 无升级、无丹药的完整53动作通关路线；每场结束气血/灵力分别46/1、24/2、36/4。页面使用实际按钮，未通过 API 写入替代操作或修改存档作弊。
- 另一路公开行动完成双功法升级、采药炼丹补给后通关；可选交易、修为增量、成本、非法动作无副作用及通关后继续成长。
- 狼战的强攻耗灵力、蓄势、重击防御减伤、先击杀无反击、零灵力拒绝强攻、败退气血1、静养免费恢复、撤退无奖励；资源上限与日志最多100条。
- 自动保存、战斗中服务重启、slot完整恢复、全局revision不回退、新局清槽、旧标签页拒绝；同请求重复返回最新快照且不重复结算，跨重启保留去重记录。
- 四请求并发同revision仅一项提交；未知/非法字段、bool版本、无穷/NaN JSON、外站Origin拒绝且不改状态。
- SQLite锁超时返回503后恢复可写；在state UPDATE之后注入requests INSERT失败，整个事务及请求账本回滚，移除故障后同ID仍可首次提交。
- 损坏数据库启动拒绝且文件SHA-256不变，不静默重置。
- 页面存档/载入确认取消不写入、取消后焦点返回、刷新续玩、新局确认清槽、键盘操作；两页版本冲突显示反馈且无状态污染。
- 浏览器注入“已提交但响应丢失”，在A待确认时打开独立真实页B并成功执行另一行动；B不继承、清空或覆盖A的pending。A刷新后重试仍复用原request_id，返回包括B行动的最新快照，两项行动各结算一次。

浏览器报告中的409及 `net::ERR_FAILED` 是明确注入的冲突和断连，保留在报告并标记 `injected:true`；无未注入控制台错误、无JavaScript异常、无未注入请求失败。脚本不会一概忽略这些错误。

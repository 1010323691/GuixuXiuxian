# 界面与交互契约

状态：已按 API 契约实现原生 HTML/CSS/JavaScript 前端；视觉岗位维护 `static/` 文件，不在前端复制游戏规则。独立验收结果由 QA 维护。

## 页面结构
游戏采用深墨青背景、古纸文字与少量旧金强调，系统中文衬线标题及无衬线正文，无外部字体和图片请求。采用章节式布局、紧凑账目和连续日志，不堆叠数值卡片。

1. 页头：游戏名、简短修行定位、当前自动保存状态；手动保存/载入与新局为次要操作。
2. 顶部摘要：姓名、境界、当前目标及关键状态进度；资源以带名称的数值账目呈现。
3. 主栏：当前场景、可进入区域、行动列表；行动旁明示收益、消耗和前置条件。战斗时原位替换为敌人状态、下一回合意图与战斗指令，不要求在多个页面来回切换。
4. 次栏：当前修行目标说明、人物细节和近期经历；日志有时间/回合或序号、结果与变化，保留历史查看入口。
5. 结局：明确通关文本与后续可用操作，不以达到隐藏状态代替可见结束反馈。

## 进入与行动
无当前游戏时显示简洁新角色表单，仅姓名，默认“归墟客”；不加入出身、职业或禀赋选择。首次创建没有旧进度无需破坏性确认。

当前状态、动作、成本、可用条件、战斗意图和结果均来自后端。突破为确定性动作，不弹确认，明示满足条件及将发生的变化。禁用动作仍显示原因；资源不足不能只靠灰色提示。

非战斗行动分为修行、游历、山海、行囊四组，用普通按钮的 aria-pressed 表达选中组，当前页面保留选择；默认显示修行。分组只决定展示，不决定可执行性。每行呈现行动名、成本/收益和禁用原因，完整 detail 保留于 title，不重复长段规则。战斗只显示后端返回的战斗动作，不显示分组按钮。

请求进行中禁用状态写入按钮并显示“进行中…”，防止重复点击。成功后使用完整权威快照刷新状态，展示本次事件与变化。前端不得先行增加资源或宣称保存成功。

## 保存与确认
每次后端成功行动自动保存于 SQLite。页头保存文字只反映已确认提交的结果，请求未确认时显示处理中或结果未确认。

提供一个手动存档 slot，显示可用性及后端 summary（姓名、境界、行动摘要），不显示 API 未提供的时间。手动保存记录当前进度；载入为恢复该 slot，并覆盖当前进度。slot 不存在时禁用载入并显示原因。

只有覆盖当前游戏的新局和手动载入使用确认。确认内容指出丢失当前未被该手动档保留的进度，提供清晰取消/继续按钮；取消不发写请求，确认区域可键盘操作，关闭后焦点返回触发按钮。具体存档持久化语义以 API 为准。

## 错误与一致性
写请求使用 request_id 与 expected_revision；完整待确认载荷持久化至当前标签 sessionStorage，刷新可恢复且标签间隔离。关闭标签后不承诺恢复原请求 ID，重新打开由 GET 获取最新状态。同次请求重试保留 ID 和原载荷，不自动产生新行动。收到版本冲突提示“进度已在其他页面更新”，重新获取状态后由玩家再决定。

网络中断不把结果直接写成失败或成功；显示“结果尚未确认”与恢复入口。若契约支持幂等重试，允许用户重试原请求；禁止自动重放为新请求。规则错误保留可读原因，存储错误不能显示“已保存”。加载失败可重试，保留已有可读内容和错误反馈。

## 响应式与可访问性
桌面约 1180px 内容区，主次栏约 2:1；760px 以下单栏，按目标、关键状态、行动、详细信息和日志排序。按钮触达高度至少 44px，无依赖悬停的必要信息，中文可自然换行，320px 宽无横向溢出。

保留语义标题、表单标签、键盘焦点和按钮文本；用数值和文字表达状态，颜色只作辅助。结果通知使用适度 aria-live，非紧急日志不持续抢读。尊重减少动态效果设置，装饰由 CSS 渐变、细线和低对比山形构成，不覆盖正文。

## 验收
实际浏览器验证新建、行动、成长、战斗、突破、结局、自动续玩、手动保存/载入和新局确认；覆盖加载、禁用、处理中、规则拒绝、网络失败与版本冲突。桌面/窄屏、键盘、焦点、日志及中文溢出由 QA 独立验证。本文是实施约束，尚不代表页面或测试已完成。

## 前端自测记录
在独立临时存档与本地 8101 服务上，使用系统 Chromium 和 Playwright 实际验证：空白姓名默认、修炼、保存、载入取消、刷新续玩、四分组切换、320px 无横向溢出，以及服务端提交后丢失响应、刷新恢复同 ID 待确认操作、幂等重试和两页版本冲突刷新。上述流程未见 JS 异常或意外控制台错误；独立 QA 的完整通关与回归结果见测试交付记录。待确认操作只保证当前标签刷新恢复，不承诺关页后恢复原请求 ID。

### R3 用户追加裁决：装备驱动挑战，持续修炼负责修为
副本、活动主要获取装备、法宝、道具和材料；法宝分修炼效率与战斗能力方向。战斗力提升后可挑战更高难度副本，获得更好的奖励；世界Boss个人伤害越高，奖励越好。单机NPC模拟边界不变，不引入真人竞争或付费。R2固定活动直接修为360+额外30预算及其39日结论撤回为历史探索，不能沿用为新方案结论；R3需要重新核定成长成本、法宝叠加边界与获取节奏，并检验装备循环和奖励保底。本轮仍为设计/独立模拟，不代表上述新增机制已实装。

R3数值裁决：基础540×境界系数/24h；基础八阶时间3/4/5/5/6/7/7/8日，共45日；成本按基础产能乘该时间生成。原3普通装备槽保留，新增本命/护持2法宝槽，每槽选择修炼或战斗方向；修炼品质每槽1–5%，其余增益合计最多5%，全部相加封顶15%，不因多件库存相乘。最高单次Boss有效伤害(best)决定权益，每周期最多3次正式尝试，按F(best)-已发权益补差；不是累加三次伤害。独立固定回合窗口评分，不复用击杀固定HP的劫影总伤害。低难装备/强化材料/保底兑换作为突破高难的补救；掉落权益和经济资产在新profile读档时保持一致，不能只保留已领奖标记。以上是后续实现约束。

需求见 `docs/iterations/MU_PRD.md`，设计见 `MU_DESIGN.md`（v2），交接见 `MU_HANDOFF.md`，现行接口见 `docs/API.md`。本条取代 D005（单机离线）、D009（手动快照/加载）中的相应部分，其余历史条目保留。

**方案变更 A → B（用户裁决）**：原设计 A 为每用户一个 SQLite 文件加用户目录与 `StoreRegistry`/LRU；用户认为“一个用户一个数据库太浪费”，改为 B：单库 `data/game.db`，进度表 `current` 以 `user_id` 为主键、`requests` 主键 `(user_id, request_id)`，认证表（账号/会话/限流）同库，WAL + `synchronous=FULL`。理由与取舍：磁盘浪费其实可忽略（单库约80KB），真正差别是文件数与运维——B 只有一个文件、一条备份命令、账号与进度恢复后必然匹配，外键由 SQLite 强制。B 的代价：隔离从文件级降为行级（漏写 `user_id` 即串号）、全站一把写锁、单文件损坏影响全站、`Store` 构造签名变化使若干测试夹具要改。缓解：①唯一数据访问层（`ProgressRepo`），进度表 SQL 只允许出现在 `storage.py` 且带 `user_id` 谓词，运行时断言+AST静态扫描+全量SQL采集三重兜底；②缩短写事务为“事务外读与计算，事务内只做版本比较更新+登记请求”，正确性由 SQLite 的比较并交换与复合主键保证，不依赖进程内锁；③在线 `--backup`、启动完整性检查。A 的半成品文件（`userstore.py`、`owner_id`、`user_version=owner` 等）按设计 1.7 处置表删除或重构，工作区残留的 `data/auth.db`、`data/users/` 视为从未发布的开发数据，不迁移。

**已拍板的默认值（PRD 第10节及交接约定，除标注外用户未另行反对）**
1. 删除手动存档/载入与检查点（`slot` 列弃用保留），`/api/save`、`/api/load` 返回404；是否另做游戏内“回到安全地点”机制不在本轮。
2. 开放注册，可用 `--no-register` 关闭；不做邀请码。
3. 存量 `data/game.db`：先校验备份，再迁入单库的待认领区；仅由运维 `--claim-legacy 用户名` 认领，严禁首位注册者自动继承；schema1 须同时给确认开关 `--migrate-save`（别名 `--migrate-data`）。
4. 找回密码：仅运维 `--reset-password`，密码用交互输入不走命令行参数；本版不做恢复码。
5. 会话：空闲7天、绝对30天；同账号最多10个会话；允许多设备同时登录，写冲突沿用 `STALE_STATE`。
6. 用户名允许中文，NFKC 规范化并按 casefold 判重；3–20位，字符集中文/字母/数字/下划线；密码8–64位。角色名与用户名分离。
7. 密码哈希 scrypt（`n=2^15,r=8,p=1`），登录与改密限流（5次/5分钟等分级）；注册即登录；`/api/session` 恒返回200；错误码 `SAVE_FAILED` 保留（用户不可见）。
8. 部署：默认仅监听本机；对外须 `--allowed-host`；开放注册上公网必须 HTTPS 反向代理并加 `--secure-cookies`，服务不内置 TLS。
9. 仅标准库，不引入 FastAPI 等第三方包。
10. 备份：`--backup` 为单文件整库在线备份（不能按用户恢复）；WAL 不支持网络盘，启动检查发现即拒绝。
11. `synchronous=FULL` 不得为性能私自降为 NORMAL；如目标机 P99 过高须记录并回报。
12. 玩家可见层术语统一为“进度/进度已同步/登录后恢复进度”，禁用“存档、读档、载入、检查点、保存位置、单机”等词（历史文档除外），由扫描测试兜底。

**待用户确认（尚无明确答复）**

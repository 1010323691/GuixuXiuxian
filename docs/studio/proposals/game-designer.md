# 主策划首版提案（待交叉评审与 PM 冻结）

## 定位与核心乐趣
中文单人文字修仙短篇：从山村散修修至筑基，闯过归墟试炼并迎来明确结局。乐趣来自读懂风险、安排修炼与补给、选择战斗招式，逐步将打不过的对手变为可以稳定战胜的目标。保留探索小故事与成长反馈，避免首版堆叠养成页签。

## 时间模型
建议行动回合制，不采用后台实时计时、离线收益或限时点击。每次修炼、采集、探索、战斗招式算一次行动；阅读、切页、查看规则、存档不推进世界。无寿命倒计时，不因停留页面或网络延迟损失进度。

## 候选系统取舍
| 首版 | 扩展候选 | 首版不采用 |
| --- | --- | --- |
| 角色创建：姓名与三项等强起始禀赋 | 更多境界与地图、功法分支、支线结局 | 联机、抽卡、付费服务 |
| 炼气三层与筑基目标、修为积累和明确突破条件 | 装备词缀、宗门关系、长期经营 | 实时挂机、寿命惩罚、永久死亡 |
| 三处区域、材料采集、固定精英与最终试炼 | 随机探索事件、更多敌人行为 | 随机突破失败损耗、隐藏命中率 |
| 三种战斗指令、丹药补给、败退恢复 | 多人队伍与复杂技能树 | 可交易经济、无限背包垃圾 |
| 引导任务、剧情日志、存档/读档/重开 | 多角色档位 | 必需在线资源或账号 |

禀赋只影响便利程度，不锁内容；首版必须先平衡普通默认角色。可将其他岗位建议中有价值的系统替换进首版，但保持一条完整可通关闭环。

## 资源闭环与防卡死
建议只保留气血、灵力、修为、灵石、药草五项，境界与功法提供固定成长。修炼免费获得修为；安全采药免费获得药草；静养免费恢复气血与灵力。药草可炼恢复药，灵石来自探索/战斗并用于可选便利升级；突破不得依赖有限或随机掉落的材料。所有消耗前明示成本和收益，不允许扣成负数。

循环：查看当前目标 → 修炼达到门槛 → 采药/炼丹准备 → 探索与战斗 → 获得升级及剧情 → 突破/解锁下一区 → 最终试炼 → 结局。败退返回安全区，失去本战未结算奖励，保留已获成长和关键道具；没有永久扣减、存档作废或不可恢复资源锁。战斗中可撤退，必需目标可重复挑战。获胜标记持久化，已领取任务奖励不可重复刷。

## 战斗可解释性
首版采用确定性回合，避免概率带来的反复读档。敌方下回合意图预告：攻击、蓄势、恢复；玩家选择普攻、运功强攻、防御或使用恢复药，随后敌方行动。展示技能成本、预计伤害/防御值、敌人意图及结果日志。建议：强攻花灵力但伤害高，防御减少本回合受伤并回少量灵力；零灵力仍可普攻、防御或撤退。若同一回合击败敌人，敌人不再反击。胜负检查与药效顺序在 GDD 明确，不留下前后端自由解释空间。

若评审决定加入概率，只用于非必需探索奖励，须显示概率、保留固定最低收益并可在测试中注入种子；不影响关键任务或突破可达性。

## 约 20 分钟通关目标
目标为初次阅读正常操作约 15–25 分钟，约 70–110 个有效行动；自动化测试以行动预算验证可达性，不能宣称已验证真实游玩时长。建议分为入门引导约 3 分钟、炼气与首战约 5 分钟、两处区域与成长约 7 分钟、最终准备/试炼/结局约 5 分钟。具体数值须由模拟与独立试玩调整，减少重复点击而不是靠延时拖长流程。

## 首版验收建议
- 新角色可完成引导、成长、补给、普通战斗、突破及最终试炼，出现清晰结局与继续游玩/重开入口。
- 默认角色存在公开可复现的通关路线，110 次有效行动内完成；额外验证零灵石、零药草、败退及低血状态仍能回到可继续路线。
- 每项行动成本、收益和禁止条件一致且可见；非法行动不消耗资源，不导致状态损坏。
- 战斗预告、行动顺序及日志与结算一致；零灵力可继续，撤退和败退均可恢复；任务奖励不能重复领取。
- 保存并重启后恢复角色、资源、解锁、任务及结局；读取损坏/不兼容档案提示明确且不覆盖有效进度。战斗中存档能力由技术方案明确，若禁用须说明原因。
- QA 独立执行完整通关、边界、存档与重开流程；实际游玩时长与未验证项分开报告。

## 交接
本文件仅为设计建议，不是冻结 GDD。需要架构确认状态权威与存档边界，开发评估最小系统复杂度，视觉确认信息密度和战斗意图表达，QA 审查可复现路线与防卡死覆盖；最终由 PM 冻结范围和数值。

## 交叉评审结论
1. 认可开发与架构的后端权威、原子提交与版本校验。确定性规则可去掉随机源和概率存档复杂度；客户端不应自行计算奖励或判断通关。
2. 认可视觉的单一当前目标与就近显示成本。突破采用确定性成功，无需“风险确认”弹窗；新局仍需破坏性确认。战斗必须常显敌方下一意图及具体伤害。
3. 开发建议 JSON 原子文件、架构建议 SQLite，建议选 SQLite 并冻结单档语义。先完成自动保存、重启续玩、损坏拒绝，不让复杂多档/恢复 UI 阻塞可玩闭环。候选精确规则移至 `docs/GDD.md`，无出身选择，等待 PM 确认。

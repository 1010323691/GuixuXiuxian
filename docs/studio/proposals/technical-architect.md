# 技术架构提案

状态：供交叉评审，尚未实施；玩法细节以之后批准的 GDD 为准。

## 交叉评审与项目经理裁决（优先于下文初案）
已阅读策划、开发、视觉提案及PM转述QA重点。接受确定性回合、无离线收益、后端动作投影。项目经理最终采纳SQLite：current、manual checkpoint与requests在同一事务提交；不使用原子JSON文件或自动备份轮转。每次成功写操作含slot保存/载入都递增全局revision；载入仅替换state，保留请求账本；新局清空slot，防止跨角色误载。无需game_id，单调revision足以拒绝旧页。损坏拒绝且保留原件，README记录停服复制数据库备份。

API明确 `view.actions` 含id/label/detail/cost/effect/enabled/reason/params/primary，UI直接展示。重复ID返回最新快照、duplicate:true、events:[]，避免原响应倒退UI。仅新局与载入确认；突破为确定性普通操作。实现候选契约见 `../../ARCHITECTURE.md` 与 `../../API.md`。下文复杂备份策略仅为早期讨论，不作为实施范围。

## 推荐与选型边界
推荐 Python 3.11+ 标准库 HTTP 服务 + SQLite + 原生 HTML/CSS/JavaScript，同源提供静态文件和 JSON API。当前机器 Python 为 3.12.14；此处只验证了版本，尚未验证程序。首版为单人本地应用，默认监听 `127.0.0.1`，不依赖账号、联网资源、Node 构建或包安装。

| 方案 | 优点 | 代价与适用范围 |
| --- | --- | --- |
| stdlib HTTP + SQLite | 开箱可运行，离线交付容易，存档事务与规则测试均无需第三方库 | 需明确编写路由、JSON 错误封装和安全限制；仅承诺本地开发/游玩，不作为公网服务 |
| Flask + SQLite | 路由、请求解析与错误处理更成熟，后续扩展容易 | 需要安装和固定依赖；其开发服务器同样不是公网生产部署方案 |

当前只有少量 API，标准库足够；若后续增加账号、多人、复杂路由或公开部署，重新评估 Flask/部署服务器，不为首版提前引入。云环境功能验证通过本地 HTTP 请求完成；若后续需要共享访问，再单独定义绑定、访问控制与部署契约。

## 最小模块划分
- `server.py`：启动参数、HTTP 路由、请求校验、静态文件白名单与统一错误返回，不计算玩法。
- `game/config.py`：版本化配置、阶段/行动/内容定义和数值；使用稳定 ID 与中文展示名分离，不在前端复制结算公式。
- `game/rules.py`：纯规则函数，输入状态、行动及可注入随机源，输出新状态与事件；不访问 HTTP、磁盘或真实时间。
- `game/storage.py`：SQLite 初始化、状态校验、事务、请求去重、备份与恢复；以存档目录参数隔离真实存档和测试数据。
- `static/index.html`、`styles.css`、`app.js`：布局样式和交互；仅提交玩家意图、展示服务器状态及事件，不决定奖励、随机结果或冷却。
- `tests/`：标准库 unittest；规则单测、存储事务测试和临时端口 HTTP 集成测试。QA 另行执行真实浏览器验收。

允许按最终范围合并小文件，保持边界即可；不建插件系统、微服务、通用 ECS 或前端框架。视觉岗位与开发岗位应先约定 DOM 区域、UI 状态字段与各自文件所有权。

## 后端权威行动与一致性
采用行动驱动的结算：所有可用行动及消耗由后端检查，后端产生随机结果并一次性保存。首版不做后台计时循环和离线收益；如 GDD 确有需要，再定义真实时间、上限及防重复结算规则。

单个 SQLite 数据库维护一个当前存档。存档元信息包含 `schema_version`、`revision`、创建/更新标识；状态含规则所需字段与有限长度事件日志。存档数据采用清晰、可校验的 JSON 状态，SQLite 表结构保持简单。所有写入使用独立连接，`BEGIN IMMEDIATE`、有限 busy timeout；不共享跨线程连接。行动流程：解析 → 查询去重记录 → 校验预期版本与行动 → 计算新状态 → 校验不变量 → 写入状态及请求结果 → 提交。事务期间不做网络或文件备份。崩溃/异常回滚，绝不返回未提交的成功。

每次写请求必须带 `request_id` 和 `expected_revision`。同一 ID、同一载荷的重试返回已保存结果，不再扣费或抽奖；同一 ID 不同载荷返回冲突。为当前游戏实例保留去重记录，首版不做易导致重复结算的短期过期。多页面或并发行动中仅一个版本匹配者成功；其余返回 `409 STALE_STATE` 并提示刷新。前端禁用处理中操作，但后端版本约束才是正确性保证。

新开局/读档恢复属于写操作，必须显式确认并带版本；服务器分配新的游戏实例 ID，旧实例写请求拒绝，避免旧标签页污染新游戏。新建角色前的空状态单独表示，不将 GET 变为隐式开局。

## 存储、备份与异常策略
SQLite 事务承担原子存储，不使用直接覆盖 JSON 文件作为唯一存档。启动时检查数据库版本及状态合法性；未知高版本拒绝写入并给出清楚说明，不盲目降级或重置。默认存档位于可配置的本地数据目录，README 明确目录及备份方式，测试永不使用默认真实存档。

提供 SQLite backup API 的一致性备份，临时输出成功后在同一文件系统 `os.replace` 发布；至少保留一份已验证备份。备份安排在成功提交后，备份失败不否认已保存的行动，返回/记录可见警告。恢复前先验证备份结构、schema 与状态不变量，并为现存数据库保留副本；暂停写入并关闭连接后替换，恢复后重新分配游戏实例 ID。损坏、磁盘满、锁超时、权限错误均不得静默当作新游戏；保留原文件，返回可操作中文错误。若自动备份/恢复超出首版范围，必须明确交付“手动一致性备份命令 + 有提示的拒绝损坏存档”，不能宣称已有自动恢复。

本地 API 仍需限制请求体大小、校验 Content-Type/动作白名单/字段类型，拒绝布尔值冒充整数；静态路由禁止目录穿越。不提供任意路径读写，不启用宽泛 CORS。写请求校验 Origin/Host，并使用同源自定义请求头或 CSRF 标识避免外站驱动本地状态变更。错误响应不泄漏回溯或文件内容，控制台保留诊断；不记录整份敏感环境。

## 拟定 API 契约
以下是协议形状建议，行动类型待 GDD 固化。所有响应 `application/json; charset=utf-8`，状态字段最终需要单独接口文档定义。

| 请求 | 意图 | 结果 |
| --- | --- | --- |
| `GET /api/health` | 服务 readiness | `{"ok":true,"schema_version":1}`；存储未就绪应非 200 |
| `GET /api/state` | 当前权威快照 | `game_id`、`revision`、`state`、`available_actions`、`events`；无开局明确为 null |
| `POST /api/new-game` | 经确认创建存档 | `request_id`、`expected_revision`、角色参数；成功返回完整新快照 |
| `POST /api/action` | 执行一个玩家意图 | `request_id`、`game_id`、`expected_revision`、`action`、`params`；成功返回完整快照与本次事件 |

统一失败为 `{"ok":false,"error":{"code":"...","message":"中文说明"}}`，必要时附当前 revision；非法 JSON/字段用 400，未知路径 404，状态/幂等冲突 409，不足以执行的行动用 422，存储不可用 503，未预期错误 500。客户端收到失败保留现有视图并提示，网络超时允许同 ID 重试；过期状态刷新后由玩家重新决定，不自动重放行动。成功事件必须随返回状态显示；重试不会再次追加日志。

## 验证建议与交付门槛
规则测试覆盖每类行动成功/前置条件失败、上下界、确定性随机边界、阶段转移和终局；禁止仅测试函数存在。存储测试覆盖保存重启、失败回滚、重复请求、不同载荷同 ID、多连接版本冲突、损坏拒绝与备份恢复。HTTP 集成覆盖 JSON/字段错误、未知路由、完整开局至代表性成长、页面可加载、静态穿越拒绝和存储故障响应。

QA 使用独立临时存档验证浏览器可操作、错误可见、按钮在忙碌/不可用时合理反馈、重复点击与多页冲突、刷新/服务器重启续玩、中文布局及键盘操作。首版必须实际运行服务与完整可玩闭环，并留存命令、通过/失败结果及已知限制；当前提案不代表任何测试已通过。

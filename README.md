# 归墟修行手札 · 凡界篇 v1.2.0

HTML/CSS/JavaScript + Python 的中文文字修仙游戏。单人本地运行，从炼气序章走向筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫，最终封印凡界界门。新角色默认长线修行：入世后在线、离线持续增长，主动玩法以装备、法宝和材料养成为主；旧角色及可选自由历练保留原行动成长。战斗、NPC经济与生产仍按行动推进。仙界只预留扩展接口，本版不可进入。

v1.2.0调整首周成长、可恢复的副本资格、七段故事与三名精英，并提供已手战通关副本的快捷结算。本轮验收与限制见[R4测试记录](docs/iterations/R4_TESTING.md)；已完成181项全量与四套真实浏览器验证，运行哈希与最后文案补丁的定向证据均已记录，不以旧版通过代替本轮验收。

世界中的师友、宗门、家族成员、商人、拍卖买家和竞技对手均为本地规则驱动的 NPC。**NPC 演武和三域模拟赛不是现实 PVP 或真实跨服联机**；不接账号、付费API、真实商城或外部服务。

## 启动

需要 Python 3.11+（本环境实测3.12.14），游戏运行没有第三方依赖，不需要 Node 或联网构建。在项目根目录执行：

```sh
python server.py --host 127.0.0.1 --port 8000 --data-dir ./data
```

在运行机器本地浏览器打开 `http://127.0.0.1:8000`。不要直接双击HTML，它需要同源Python接口。按 Ctrl+C 停服。服务默认只监听本机，不是公网多人部署方案；云端onboarding没有本地网页预览入口。

如果已有旧版数据，先停止使用同一数据目录的旧进程，再执行：

```sh
python server.py --migrate-save --host 127.0.0.1 --port 8000 --data-dir ./data
```

迁移会先验证并生成唯一的 `data/game.schema1.*.bak.db` 原版备份，再一次性升级当前档与手动档；原资源、战斗、版本序号和请求账本保留。没有迁移标志时拒绝隐式修改旧库。新目录直接建立schema2，损坏或未知高版本拒绝启动且不静默重置。

v1.1长线的内容升级保持schema2：停服后使用新版启动，会先生成唯一的 `data/game.r3-before-r4.*.bak.db` 备份，再一次性升级当前档与手动档。已获境界、当前阶段的精确完成比例和资产保留，已封界储备不按新成本重标；全局revision递增，旧检查点不能重复折算或重领资格。自由历练不自动转换。升级失败保留原件；不要让新旧服务同时使用同一数据目录。

## 从何玩起

1. 输入道号，完成青岚序章：修炼、突破、妖猿与石傀首胜，筑基后击败归墟之影。
2. 点击明确显示的“进入完整修仙界”。序章保留为只读旧事，凡界使用独立的修为、气血和背包，入世资源只发一次。
3. 在“人物”觉醒灵根/体质、学习功法；“九州”安全采集或凝灵；“四艺”制作可实际使用的丹药、装备、符箓与阵法。
4. 长线角色先看总览近期目标，补齐三器，低难取得强化材料，挑战高难获取更好装备；法宝选择修炼增速或战力。七段行纪按境界与前置推进，三名支线精英分别考验破盾、防毒和保蓝；日常项目、周轮换、三副本特色机制和世界Boss提供不同玩法，均不直接堆修为。自由历练仍保留原即时道行来源。
5. 完成八境守关、阶段条件和三秘境，交付“合拢裂隙”，达成本版凡界结局。结局后仍可经营、养成、挑战高难副本与开启新赛季。

操作前显示成本、效果、条件和禁用原因；字段表单由后端给出允许范围。每页事项可检索、分批浏览，全部动作仍可展开。战斗中有全局交锋提示，指令置顶；敌人意图、实际伤害和丹符消耗均可查看。

长线入世后基础修为持续增长，无待领取仓容或全球每日修为封顶；基础八阶段45日，法宝等增益相加最多15%，具体历日取决于获取与上线突破时机。短序章不计入这45日。低难保底、制作、分解、兑换提供成长补救，境界不靠随机稀有掉落锁死。前段基础12小时结丹、第2日元婴、第5日化神，仍需及时突破和备齐条件。详见[当前长线玩法手册](docs/R4_PLAYING.md)；[原手册](docs/PLAYING.md)保留自由历练与共同世界系统说明。

三器及两法宝使用独立实例；法宝修炼型或战力型择一。三副本三难度按章节固定敌强，正式掉落资格入世初始3次、每8小时恢复1次、容量3（含进行中预约），满额不囤时间；失败/退出归还预约，成功消费一次，装备五模板轮换与分难度品质保底。同章同难真实手战成功一次后可消耗正式资格快捷结算，与手战共用掉落、保底和副本奖励，不额外消耗丹药；零资格仅可手战练习，新难度/Boss/精英不能扫荡。高难终场分别考验防毒、破盾和保蓝。世界Boss每UTC日3次正式尝试、每场最多12玩家回合，取个人最高单次有效伤害并补发奖励差额，明确排除同行NPC伤害；达到奖励上限仍可保留成绩。日常三选一与周主题奖励材料，不增加副本资格或修炼上限。

旧自由历练没有离线收益，保留行动制完整通关体验。两个模式均没有永久死亡；静养、采集、凝灵免费，失败保留永久成长，核心玩法不依赖真人、付费或外部服务。

## 存档与安全恢复

所有成功写入通过 SQLite 事务自动保存到 `data/game.db`，刷新/停服重启恢复完整进度，战斗和NPC订单也保存；长线修为根据经过时长结算，无需网页保持打开。

长线入世后的手动档为**安全位置检查点**：载入保留当前成长与突破花费、物品、经济、剧情、战斗、世界行动时间和奖励资格，只在安全条件下恢复同角色位置；不能退回序章或用旧档复活已分解装备。正在战斗/探索时保留当前位置。未入世序章及自由历练仍完整恢复手动世界快照。新局会替换当前角色并清空手动检查点。

全局revision和请求去重账本不回退，重复请求不会重复扣费或领奖；成长、消耗、奖励与请求同事务提交。网络结果未知时重试原请求，不能盲目生成新行动。查看/切页仅只读预览，不推进经济或写存档。

手动档与当前档在同一数据库中，不能代替灾备。独立备份需**先停服**再复制完整数据库，使用未占用文件名，不覆盖原件：

```sh
mkdir -p backups
cp data/game.db backups/game-before-change.db
```

恢复前停服并另存当前数据库，再复制已知良好备份。schema1备份需通过显式迁移重新升级。若存在未完成的 `game.db-journal`，先保留完整目录并诊断，不要只替换某一文件或删除坏档来“修复”。启动中文错误会给出版本/损坏提示。

## 开发与测试

```sh
python -m unittest discover -s tests -v
python -m tests.browser_smoke
python -m tests.browser_world
python -m tests.browser_r3
python -m tests.browser_r4
```

第一项仅用标准库。四个真实浏览器脚本需要可选开发工具 Python Playwright 和系统 Chromium，当前使用 `/usr/bin/chromium`；它们不是游戏运行依赖。测试各用独立临时目录和端口，不读写玩家 `data/`。本版以[R4测试记录](docs/iterations/R4_TESTING.md)为准，原[R3测试记录](docs/iterations/R3_TESTING.md)保留v1.1证据，原[凡界测试记录](docs/iterations/WORLD_TESTING.md)与[覆盖矩阵](docs/iterations/COVERAGE.md)保留为旧版本证据。注入时间的完整通关测试不是真人月余观察。

结构：`game/config.py`、`world_config.py`、`r3_config.py`和`gameplay_config.py`定义内容；`rules.py`、`world.py`、`loot.py`、`activities.py`、`journey.py`负责规则与权威投影，`cadence.py`处理恢复资格，`growth.py`处理精确时间积分，`storage.py`负责事务/迁移，`server.py`提供同源HTTP，`static/`呈现真实交互。实际新契约见[R4接口](docs/iterations/R4_API.md)及仍适用的[R3接口](docs/iterations/R3_API.md)，五岗位设计、质疑和修复见`docs/studio/`与`docs/iterations/`。

源码打包与独立解包验证（标准库，无需浏览器依赖）：

```sh
python scripts/build_release.py
python scripts/verify_release.py dist/guixu-mortal-v1.2.0.zip artifacts/r4-qa/package-smoke.json
```

归档排除玩家data、备份数据库、Git、字节码和其他压缩包；迁移测试所需的虚构旧档JSON已随源码提供，不依赖旧版本发行包。ZIP校验摘要见dist/SHA256SUMS，包构建/最终运行报告保留在当前工作目录artifacts/r4-qa中，避免把包含自身摘要的报告再塞入同一个包。

# 归墟修行手札 · 凡界篇 v1.2.0

HTML/CSS/JavaScript + Python 的中文文字修仙游戏，现为**多账号在线服务**：玩家用用户名和密码注册登录，各自的修行进度互相隔离，由服务端自动同步，换设备登录即可继续。从炼气序章走向筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫，最终封印凡界界门。新角色默认长线修行：入世后在线、离线持续增长，主动玩法以装备、法宝和材料养成为主；旧角色及可选自由历练保留原行动成长。战斗、NPC经济与生产仍按行动推进。仙界只预留扩展接口，本版不可进入。

v1.2.0调整首周成长、可恢复的副本资格、七段故事与三名精英，并提供已手战通关副本的快捷结算。本轮验收与限制见[R4测试记录](docs/iterations/R4_TESTING.md)。多用户在线化（账号、隔离、自动同步）是其后的增量改动，需求与设计见[MU需求](docs/iterations/MU_PRD.md)、[MU设计](docs/iterations/MU_DESIGN.md)，**其全量测试、浏览器套件与部署实测以QA记录为准，未验证项不视为已通过**；R4/R5的历史通过数不代表多用户改动之后的状态。

世界中的师友、宗门、家族成员、商人、拍卖买家和竞技对手均为规则驱动的 NPC。**NPC 演武和三域模拟赛不是现实 PVP 或真实跨服联机**；账号之间只有数据隔离，没有聊天、交易、组队或任何互动；不接邮箱/手机号、付费API、真实商城或外部服务。

## R5 自动斗法（已接入正式游戏）

正式游戏的战斗已改为**自动斗法**：点击式出招（普攻/强攻/防御/丹/符/撤退）已退役，战斗中只剩「自动斗法」策略按钮（均衡/稳妥/强攻/节制，序章为单一「自动斗法」）。服务端一次请求内按有界规则演算整场并原子结算，页面用云海御空战报回放复盘；战力型本命/护持法宝按冷却独立出击与回护。规则、接口与限制见[R5接入说明](docs/iterations/R5_INTEGRATION.md)。

独立实验入口仍保留：`python prototypes/r5-combat/server.py --port 8001`，浏览器打开 `http://127.0.0.1:8001`，它不接正式账号、成长或掉落。见[实验玩法与启动](prototypes/r5-combat/README.md)、[工作室设计裁决](docs/iterations/R5_DECISIONS.md)和[独立实测状态](docs/iterations/R5_LAB_TESTING.md)。

[独立实验包](dist/guixu-r5-combat-lab.zip)与[校验值](dist/R5-LAB-SHA256SUMS)已生成。实验通过14项及7组真实浏览器检查；发布包另行独立解包重跑14项、启动与HTTP流程验证，解包证据见 `artifacts/r5-review/package-smoke.json`。

## 启动与首次使用

需要 Python 3.11+（本环境实测3.12.14），游戏运行没有第三方依赖，不需要 Node 或联网构建。

Windows 一键启动：双击根目录 `启动游戏.bat`，会使用 `./data` 启动服务并自动打开浏览器；游戏已在运行时只打开浏览器，端口被占用时给出提示。可追加参数，如 `启动游戏.bat --port 8010`，也支持 `--host`、`--allowed-host`、`--no-register`、`--secure-cookies`。它**不会**执行旧版数据迁移：发现未迁移的旧库时服务拒绝启动并显示原因。其他系统可用 `python scripts/launch.py`。

也可在项目根目录手动执行：

```sh
python server.py --host 127.0.0.1 --port 8000 --data-dir ./data
```

打开 `http://127.0.0.1:8000`，首次会看到登录/注册面板。不要直接双击HTML，它需要同源Python接口。按 Ctrl+C 停服。

**创建第一个账号**有两种方式：①在网页上注册（用户名3–20位，中文/字母/数字/下划线，密码8–64位；注册即登录；没有邮箱或手机号）；②运维在命令行创建，密码以交互方式输入（不会出现在命令行参数里）：

```sh
python server.py --create-user 玩家名 --data-dir ./data
```

忘记密码没有自助找回，由运维重置，并使该账号全部登录失效：`python server.py --reset-password 玩家名`。已登录玩家可在界面的账号菜单中修改密码或退出登录。同一账号可多设备同时登录；两个页面同时操作时，后提交的一方会提示“进度已在其他页面更新”并自动刷新。

**进度自动同步**：每个动作由服务端在数据库事务提交后才返回成功，顶栏显示“进度已同步”；提交失败会显示“进度保存失败，请稍后重试，当前操作未生效”，此时可原样重试，不会重复扣费或领奖。没有手动保存或读取进度的按钮，刷新页面或换设备登录即恢复。吐纳等按时间累积的内容由服务端按账号结算，离线不影响其他账号。

## 部署与运维

默认只监听本机，信任度最高。要让局域网或公网访问，请注意：

- **允许主机**：用 `--host 0.0.0.0`（或具体地址）监听后，必须用 `--allowed-host 域名或IP[:端口]`（可重复）声明允许的访问主机名，否则请求会被拒绝（防DNS重绑定）。不支持通配符。
- **开放注册上公网必须使用HTTPS反向代理**（如 Nginx/Caddy）并加 `--secure-cookies`：登录凭证改用 `Secure` 的 `__Host-` Cookie，且允许 `https://` 来源。明文HTTP下密码和会话会被窃听；服务本身不内置TLS。反代之后再加 `--trust-proxy`，登录限流才能按真实来源地址区分（只在可信反代后启用，否则来源地址可被伪造）。反代须保留 `Host` 头，并转发 `X-Forwarded-For`。
- **关闭注册**：`--no-register` 后只有 `--create-user` 创建的账号能登录。
- **登录安全**：密码以 scrypt 加盐哈希保存；同用户名/来源连续输错会被限流（429 与等待提示）；会话空闲7天、绝对30天过期。scrypt 在目标机的实际耗时（设计预期约100–200ms）尚待实测，参数写在账号记录里可调整。
- **数据位置与文件系统**：所有账号的进度、登录信息都在一个数据库文件 `data/game.db`（运行期间还会出现 `game.db-wal`、`game.db-shm`，属正常，请勿单独删除或手拷）。数据库使用WAL，**需要本机文件系统，不支持网络盘/部分容器共享卷**，启动检查发现不支持会拒绝启动。数据目录需要持续可写，磁盘占用随玩家操作次数缓慢增长（每次成功操作登记一条请求记录，暂无自动清理）。
- **备份**：`python server.py --backup --data-dir ./data` 在线备份（**可不停服**，不阻塞游戏），产物为 `data/backups/game.<UTC时间>.bak.db`，随后自动校验完整性与行数，不覆盖已有文件。这是**整库**备份，**不能按用户单独恢复**，也不是即时灾备——请用计划任务定期调用并把备份拷离本机。不要在运行中直接复制 `data/game.db`。恢复：停服，删除 `game.db-wal`、`game.db-shm`，用备份文件替换 `game.db`，再启动。
- **运维命令**一次性执行后退出、不启动服务：`--create-user`、`--reset-password`、`--legacy-status`、`--claim-legacy`、`--migrate-multiuser`、`--backup`，同一时间只能给一个。除 `--backup` 外建议先停服。

### 旧版数据升级

如果 `data/game.db` 是升级前留下的旧格式文件，服务会**拒绝启动**并提示迁移，不会自动改动或继承。请先停服，再执行：

```sh
python server.py --migrate-multiuser --data-dir ./data
```

第1版（schema1）旧数据须再追加确认开关 `--migrate-save`（别名 `--migrate-data`）。迁移会先把旧库校验备份为 `data/game.pre-multiuser.<时间>.bak.db`（永久保留、不覆盖），再建立新布局并把旧进度放进**待认领区**；任何账号登录都看不到它，中途失败则原库保持不变。随后让目标玩家先注册（或用 `--create-user` 创建）账号，再由运维认领：

```sh
python server.py --legacy-status --data-dir ./data
python server.py --claim-legacy 玩家名 --data-dir ./data
```

认领是一次原子操作，认领时才套用必要的内容升级（旧长线先升级到当前规则，自由历练与schema1规则不自动转换）；目标账号已有进度时需追加 `--force`，覆盖前会先整库备份。已被认领的数据不能重复认领。旧版的手动备份槽已随多用户化退役，认领后只有当前进度。项目开发期间若出现 `data/auth.db`、`data/users/` 等未发布的试验数据，程序不读取，可手工删除。

## 从何玩起

1. 注册或登录账号，输入道号，完成青岚序章：修炼、突破、妖猿与石傀首胜，筑基后击败归墟之影。
2. 点击明确显示的“进入完整修仙界”。序章保留为只读旧事，凡界使用独立的修为、气血和背包，入世资源只发一次。
3. 在“人物”觉醒灵根/体质、学习功法；“九州”安全采集或凝灵；“四艺”制作可实际使用的丹药、装备、符箓与阵法。
4. 长线角色先看总览近期目标，补齐三器，低难取得强化材料，挑战高难获取更好装备；法宝选择修炼增速或战力。七段行纪按境界与前置推进，三名支线精英分别考验破盾、防毒和保蓝；日常项目、周轮换、三副本特色机制和世界Boss提供不同玩法，均不直接堆修为。自由历练仍保留原即时道行来源。
5. 完成八境守关、阶段条件和三秘境，交付“合拢裂隙”，达成本版凡界结局。结局后仍可经营、养成、挑战高难副本与开启新赛季。

操作前显示成本、效果、条件和禁用原因；字段表单由后端给出允许范围。每页事项可检索、分批浏览，全部动作仍可展开。战斗中有全局交锋提示，自动斗法策略置顶；敌人意图与机制反制提示可看，提交后战报回放展示逐拍伤害、法宝出击/回护与丹符实际消耗。

长线入世后基础修为持续增长，无待领取仓容或全球每日修为封顶；基础八阶段45日，法宝等增益相加最多15%，具体历日取决于获取与上线突破时机。短序章不计入这45日。低难保底、制作、分解、兑换提供成长补救，境界不靠随机稀有掉落锁死。前段基础12小时结丹、第2日元婴、第5日化神，仍需及时突破和备齐条件。详见[当前长线玩法手册](docs/R4_PLAYING.md)；[原手册](docs/PLAYING.md)保留自由历练与共同世界系统说明。

三器及两法宝使用独立实例；法宝修炼型或战力型择一。三副本三难度按章节固定敌强，正式掉落资格入世初始3次、每8小时恢复1次、容量3（含进行中预约），满额不囤时间；失败/退出归还预约，成功消费一次，装备五模板轮换与分难度品质保底。同章同难真实手战成功一次后可消耗正式资格快捷结算，与手战共用掉落、保底和副本奖励，不额外消耗丹药；零资格仅可手战练习，新难度/Boss/精英不能扫荡。高难终场分别考验防毒、破盾和保蓝。世界Boss每UTC日3次正式尝试、每场最多12玩家回合，取个人最高单次有效伤害并补发奖励差额，明确排除同行NPC伤害；达到奖励上限仍可保留成绩。日常三选一与周主题奖励材料，不增加副本资格或修炼上限。

旧自由历练没有离线收益，保留行动制完整通关体验。两个模式均没有永久死亡；静养、采集、凝灵免费，失败保留永久成长，核心玩法不依赖真人、付费或外部服务。

## 进度同步与恢复

所有成功写入通过 SQLite 事务自动提交到 `data/game.db`，刷新/停服重启/换设备登录都恢复该账号的完整进度，战斗和NPC订单也同步；长线修为根据经过时长结算，无需网页保持打开。提交成功后才向页面报告成功；提交失败整次回滚，页面如实提示。

全局revision和账号内请求去重账本不回退，重复请求不会重复扣费或领奖；成长、消耗、奖励与请求同事务提交。网络结果未知时重试原请求，不能盲目生成新行动。查看/切页仅只读预览，不推进经济，也不写库。新局会替换当前账号的角色并需要确认；没有可回退到过去的功能，因此操作前请留意确认提示。

服务启动时检查数据库完整性与布局版本：损坏、版本未知或旧格式文件拒绝启动并保留原件，不静默重置；启动中文错误会给出提示。若发现 `game.db-wal` 残留，请保留整个数据目录并诊断，不要只替换或删除其中某一个文件来“修复”。灾备与恢复步骤见上文“部署与运维”。

## 开发与测试

```sh
python -m tests.parallel
python -m unittest discover -s tests -v
python -m tests.browser_smoke
python -m tests.browser_world
python -m tests.browser_r3
python -m tests.browser_r4
```

前两项仅用标准库（第一项为并行白盒全量，可追加子串只跑部分）。四个真实浏览器脚本需要可选开发工具 Python Playwright 和系统 Chromium；它们不是游戏运行依赖，本机未安装时必须如实记为“未运行”。测试各用独立临时目录和端口，不读写玩家 `data/`；多账号隔离、并发、自动同步、迁移认领与文案扫描的测试以 `tests/` 内新增套件为准。本版以[R4测试记录](docs/iterations/R4_TESTING.md)为v1.2规则证据，原[R3测试记录](docs/iterations/R3_TESTING.md)保留v1.1证据，原[凡界测试记录](docs/iterations/WORLD_TESTING.md)与[覆盖矩阵](docs/iterations/COVERAGE.md)保留为旧版本证据；多用户化之后的通过数以最新QA记录为准。注入时间的完整通关测试不是真人月余观察。

结构：`game/config.py`、`world_config.py`、`r3_config.py`和`gameplay_config.py`定义内容；`rules.py`、`world.py`、`loot.py`、`activities.py`、`journey.py`负责规则与权威投影，`cadence.py`处理恢复资格，`growth.py`处理精确时间积分，`storage.py`是唯一数据访问层（`Database`、`ProgressRepo`、`Store`，按 `user_id` 隔离、短事务乐观提交），`legacy.py`负责旧版数据迁移与认领，`auth.py`/`settings.py`处理账号、会话与部署参数，`admin.py`是运维命令，`server.py`提供同源HTTP，`static/`呈现真实交互。实际接口见[API](docs/API.md)、[R4接口](docs/iterations/R4_API.md)及仍适用的[R3接口](docs/iterations/R3_API.md)，五岗位设计、质疑和修复见`docs/studio/`与`docs/iterations/`。历史文档描述的是升级前的旧版行为，现行行为以本文件、API.md和MU设计为准。
